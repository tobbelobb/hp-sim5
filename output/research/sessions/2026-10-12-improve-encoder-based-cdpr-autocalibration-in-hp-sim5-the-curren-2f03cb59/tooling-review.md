# Controlling autocal speed comparisons and reviewing the research harness

Status: complete retrospective. No new experiments were run for this review. Benchmark and tooling additions below are proposals, not tested capabilities or measured improvements.

The user correctly identified that patience-driven stopping makes the 160-point and 200-point full-run totals unsuitable for isolating collection speed. The primary objective remains a good final fit, with one-click operation and automatic stopping. This review separates that product objective from controlled research measurements and records which tools were actually used.

## What the existing timing evidence supports

E02 and E24 collected 160 and 200 points, took 5011.394 and 5659.096 simulated seconds, and selected 2.53079 and 2.38435 mm anchor-RMSE models. These are two observed outcomes of an adaptive policy. Neither the point count nor the sweep choices, recovery work and stopping path were fixed. They do not estimate a causal change in collection throughput or a distribution of time to acceptable accuracy. The comparison with the older reference is also descriptive, including earlier code changes. My earlier emphasis on beating its total time was too strong as a speed claim.

Dividing total time by point count does not solve this: force tuning and startup are amortized, points have different travel distances and roles, and recovery, returns, fitting and discarded measurements contribute differently. The 40.464-second difference between E19 and E24 is likewise an observed full-run difference, not a controlled estimate of the return routine's runtime cost.

E06/E09 provide narrower evidence: specified bounded returns finished faster from matched initial encoder observations, with matching zero final encoder lengths. They do not establish equal final physical pose or overall calibration benefit. E15/E17 provide the stronger controlled robustness result: changing means on captured inputs repairs a paired fit failure. Neither result implies a generally faster full-auto workflow.

Evidence: [full-run comparison](E26-mean-only-comparison.json), [combined-run comparison](E23-final-comparison.json), [bounded physical returns](E09-physical-returns.json), [paired averaging fits](E17-stable-mean-pilot.json).

## Three separate benchmark contracts

1. **Fitting compute:** replay identical recorded input bytes with fixed initial parameters, random seeds, solver budgets and thread settings. Measure optimization, filtering, ranking and planning separately; distinguish first-call initialization/JIT from steady-state runs. Run timed jobs without competing workloads. This isolates compute changes without moving the robot.
2. **Collection throughput:** execute an explicit ordered acquisition plan from a declared fresh world configuration, with the same targets, point roles, forces, sample counts, feeds and safety/settling criteria. Disable adaptive replanning and patience termination only in this research mode. Count attempted, accepted, retried and discarded points. Compare movement, settling, force tuning, sampling and return intervals separately. Repeat paired initial conditions; matching a build hash alone is insufficient. This tests whether the same work gets done faster.
3. **End-to-end quality versus cost:** allow each algorithm its own planning and compare geometrical accuracy at common simulated-time or movement budgets. Record the patience decision and selected candidate at each iteration. A research-only continuation mode could record the first normal stopping decision and continue to a declared cap without applying later candidates to that saved result. Evaluate both the normal stopping result and the extended quality curve. Repeat across layouts and perturbations, reporting success probability, error quantiles and time to acceptable accuracy. Runs that exhaust the budget remain failures/censored observations rather than disappearing from the average.

For the third contract, define acceptable geometry before the run, using simulator truth and independent task-space evaluation. Keep that evaluation separate from the encoder-only fitting/selection score. Anchor RMSE and task-position error answer different questions; the existing derived grid metric is not an independent physical positioning measurement. Initial calibration research should use a small fixed matrix of layouts and conditions, then expand only when a change survives those controls.

In production, preserve the current one-click patience workflow. Research modes should be declared in the experiment manifest and leave production defaults unchanged. Fixed budgets make comparisons reproducible; they need not become the user's stopping condition. An eventual uncertainty-based stop needs its own validation because the current selection score already disagrees with geometry.

## Trust and fidelity

The headless recordings were useful and internally auditable: effective configuration and source hashes, raw replies, fitted outputs, measurement counts, and stopping events could be checked against each other. That supports trusting them as evidence about this implementation and simulated model. It does not establish hardware fidelity, cross-backend parity, or generality across robot layouts.

A preflight pass checks tool readiness, not calibration accuracy. Matching scene/RRF hashes controls some inputs, not every floating-point state or adaptive decision. Derived geometry metrics are explicitly model-based. A useful future fidelity test would replay matched bounded command trajectories across browser/headless/Python backends, comparing defined frame conventions, encoders and poses within declared tolerances; hardware comparison remains separate. No such parity experiment was performed here.

## Proposed tooling improvements, in priority order

1. **A fixed-work acquisition benchmark and a standard numeric summary.** Accept an immutable plan, pairing ID and fresh-world conditions. Emit phase durations in simulated seconds and wall seconds, physics steps, travel distance, attempted/accepted/retried points, fitting time, and the first patience-stop decision. A common-budget adaptive benchmark is a separate mode. These modes would have prevented confusing policy outcomes with throughput.
2. **Explicit phase spans in the recorder.** Each span should have an operation/parent ID, world generation and collector session, start/end simulation steps and monotonic wall timestamps, outcome and point role. Separate exclusive time from nested time. Preserve sparse command events even when physical frames are sampled. Do not require inferring operation type from source filenames or assigning a stale simulation clock to a logical event. This makes settling versus transport versus solver costs directly answerable.
3. **Immutable per-job variants and complete manifests.** Let a job select a source snapshot or revision without editing the running workspace or building a temporary checkout manually. Record effective world/collector/solver settings, seeds, initial-state recipe, numerical environment, recorder policy and paired-run identity. Timed wall comparisons need serial execution or explicit resource isolation. The incomplete temporary checkout caused the preserved E07 recorder failure before physics; better variant support would remove that failure mode.
4. **Compact tool discovery and results.** Return essential status fields first: job state, phase, points/fits, simulated/wall time, stop reason and manifest path. Make logs, full artifact lists and documentation opt-in, with cursors for new events. Describe tools briefly and expose common instructions once as a resource. A one-page workflow map should route offline replay, bounded physics, full-auto, RRD queries and browser work. Some context clutter was my own overly broad discovery/read calls, but the repeated tool preambles amplified it.
5. **A supported RRD profiling/query helper and small summary sidecar.** Provide filters for phase spans, noise replies, fits and stopping, with documented session ordering and clock units. Preserve full RRDs for audit; let most comparisons read small structured summaries. Recording reduction should retain provenance and terminal events rather than sacrificing trust for disk space.
6. **Numerical robustness diagnostics for the algorithms.** Add a replay stress matrix with tiny encoder perturbations and alternative valid averaging orders, recording constraint margins, retained-point masks, optimizer termination, recovery reasons and geometric errors. A cost-100 sentinel should expose its reason in stage artifacts. Test numerical scaling/centering before changing defaults. Treat ranking accuracy and observation coverage as separate research targets.

The algorithm's stage separation, recovery and automatic stopping are useful foundations. The observed sensitivity to approximately 1e-13-degree mean changes indicates that numerical invariance deserves direct testing. Fewer points should be pursued through informative excitation and a validated quality-versus-cost measure, not an unvalidated thinning rule. All proposed benchmark, parity and diagnostic changes above remain **not tested**.
