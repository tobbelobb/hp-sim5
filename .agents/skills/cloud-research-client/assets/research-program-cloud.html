Ownership

Three reasoning roles, several ordinary processes

The worker and reviewer are separate model contexts. The controller, queue bridges, physics supervisor and Viewer are software processes; they receive parameters and execute code.

Human

Question & steering

Sets the purpose and constraints, changes direction and asks for continuation. Instructions become accepted human-input and decision records.

Interface: the existing manager conversation.

Model · manager

The current cloud chat

Chooses hypotheses, alternatives, finite budgets and the next useful investigation. Acts as the broker that spawns, binds and stops actual authenticated cloud actors.

Tools: program CLI, bridge CLI, collaboration.spawn_agent, wait_agent, interrupt_agent, and normal permitted repository tools. No manager MCP server.

Deterministic · host

Program controller

Retains SQLite memory, reservations, worker/reviewer processes, deadlines and cleanup across short CLI calls. It validates requests and admissions; it does not choose research questions.

Tools: file queue, SQLite, existing launcher, review guard, Git result archive. One host per store.

Model · worker

One bounded investigation

Receives an assignment, recorded strategy, human direction, execution settings and limits. Investigates, runs authorized tools, preserves failures, and writes reports and its final output.

Tools: repository commands under platform permissions; hp_sim5 MCP through the file relay; its assigned Rerun attachment when enabled.

Model · reviewer

A fresh evidence review

Inspects a fixed report, diff and selected assets. Returns structured JSON with a scoped finding, verdict, checks, limitations and code readiness. The manager cannot edit that verdict into acceptance.

Tools: permitted repository/file inspection. No supervisor or Rerun relay. Read-only intent and integrity checks; the platform permission profile still applies.

Deterministic · runtime

Launcher & research services

The existing research-agent starts the continuing native world, RRF and collector. Jobs may own separate worlds. Rerun inspects live or saved recordings; a browser page owns its own simulation world.

Lifecycle belongs to the launcher/supervisor. The cloud tool relay forwards actual MCP calls; it adds no physics engine.

Execution timeline · one normal iteration

From a question to reviewed knowledge

01 · MANAGER → CONTROLLEROpen the program

--cloud --question creates durable memory and an attachment. Opening starts no physics world. Readiness checks probe the launcher's environment.

02 · MANAGERChoose & fund work

Record alternatives, scope and expected observations. Commission an explicit HP3/HP4 assignment; reserve worker time, startup margin, review and cleanup.

03 · CONTROLLER → LAUNCHERStart the worker

worker_start / run_once validates readiness before charging an attempt. The existing batch launcher starts services and calls the cloud client bridge.

04 · MANAGER → CLOUD ACTORBroker a real subagent

Read the queued prompt/instructions; verify current ownership; spawn a real actor; bind its actual ID. The queue itself cannot invoke the platform's model service.

05 · WORKER → FILE RELAY → MCPInvestigate & report

The worker calls real supervisor/Viewer tools through the launcher's permitted context. It writes evidence and its final response. The manager acknowledges actual completion.

06 · MANAGER → REVIEWERFreeze & review

submit copies and hashes selected evidence. review_start queues a separate actor with a fixed target and JSON response schema.

07 · CONTROLLER + MANAGERAdmit & decide

review_apply checks identity, integrity and contract. Scientific support and code readiness remain distinct. The manager updates strategy and records its next decision.

08 · MANAGER → CONTROLLERClean up & save

Stop owned work, verify launcher cleanup, update reports and save small results with save {"commit":true}. Only that archive is committed; no push is automatic.

Two queues, two purposes

Actor queue: the bridge waits for the parent chat to supply a real worker/reviewer and acknowledge its final-output hash.

Tool queue: the worker sends file envelopes to a launcher-owned process that calls hp_sim5 or its assigned Rerun MCP server. Reviewers receive no tool relay.

Deadlines and stops

The controller/launcher and review guard enforce wall deadlines; the actor bridge adds no separate ten-minute limit. Its cancellation acknowledgement window is 45 seconds.

Cancellation requires both stopping the actual cloud actor and observing native cleanup. Numerical budgets remain contracts/estimates except where production tools enforce them; arbitrary shell compute is not fully metered.

Shared CLI operations also include graph queries, approach strategy, accepted steering, pause/resume, recovery, optional worker pools and combined-patch checks. Advanced pools and patch integration were not demonstrated live in this audit.
