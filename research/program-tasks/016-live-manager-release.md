# 016: Prove and document the complete chat-driven manager

Outcome: demonstrate the release contract in [MANAGER.md](MANAGER.md) through the
actual manager and existing research launcher, then ship accurate usage docs.
This card is the completion gate, not another architecture review.

Start with a concrete research question and practical constraints in a supported
repository-connected chat. Use saved autocal/HP4 evidence for cheap preparation;
choose a bounded production experiment that tests manager/worker integration.
Set explicit lower counts, steps/simulated time, points and wall limits from
workload costs before the live operation. Targeted fits, native/headless runs and
simulated collection are allowed; use supported speedup and suitable recording.

Required demonstration:

1. Question-only chat creates/resumes a durable program, identifies at least two
   approaches and delegates a targeted assignment through `hp-sim5-research-agent`.
2. At least two managed investigations complete through submission and separate
   evidence-first review. At least one uses a real production physics, fitting
   or collection tool. The other can reuse saved evidence. A useful scoped
   negative/inconclusive result changes route priority or parks a route.
3. Chat answers a knowledge/support query with citations and distinguishes what
   is known, unknown, promising and retired. A controlled evidence-withdrawal
   exercise uses actual graph queries and preserves alternative support.
4. The human steers the program and interrupts/stops an owned live attempt.
   Partial evidence and actual cleanup boundaries survive. A fresh manager chat
   reconstructs the program and continues without duplicate workers or claiming
   the old physics world was restored.
5. Exercise ordinary-chat CLI operation and the dedicated manager chat/attachment
   route. A fake CLI transcript or launcher dry-run cannot replace both live
   manager/worker evidence and actual coding-client interaction.

Reuse the earlier pool/integration fault tests; do not multiply expensive physical
runs to repeat them. Save commands, source/config/input hashes, attempt IDs,
budgets/actual observations, review identity/checks, graph queries, decisions,
failures and a short user-facing account. Label the pilot's small scope; it tests
research management, not guaranteed algorithm improvement or hardware accuracy.

Update research/program.md, README, manager/worker prompts and the architecture
map around the implemented entry points. Give the exact question-only prompt,
continue/overview/why/steer/pause/stop/resume examples and prerequisites. Explain
where graph memory lives, how to inspect/export it, worker access and measured
versus enforced limits. Remove obsolete “manager not implemented” notices only
after this proof; preserve historical reports.

Run relevant focused manager/launcher/graph tests once for the final candidate,
plus any applicable repository delivery gate. If credentials/runtime/client
access or a real defect prevents a required demonstration, mark the card blocked
with retained partial evidence; do not declare success from mocks or fabricate
a research result. When all criteria pass, mark the manager release complete
and leave future scientific investigations as program work, not missing product
implementation. Make one task-owned commit and do not start another task.

## Blocked attempt, 2026-10-24

The [actual pilot](../../output/research/sessions/2026-10-24-live-manager-release/report.md)
created a durable question, two approaches and a finite allocation through the
ordinary CLI/file host. It dispatched the real existing worker in an isolated
worktree. Native build failed at missing Node-API headers before tool/client or
science execution. Dedicated Codex and genuine separate review reached read-only
app-server initialization failures. Stock unmodified MCP initialization timed out.

The attempt fixed a genuine compatibility defect: disabled legacy MCP server
tables need valid transports, and whole-table replacement avoids inherited HTTP
URL conflicts. Actual installed-client parser checks and focused tests pass.
Graph query/withdrawal with alternative support, steering, pause/resume, recovery,
stop, export and a fresh CLI host were exercised. These are partial interface
results, not two completed scientific investigations or live-world stop proof.

The gate stays blocked until a working native runtime, writable/authenticated
coding client and stock MCP transport can complete the required production-tool,
separate-review, replanning and live interruption/recovery demonstration. Scientific
hypotheses remain not tested. No `MANAGER_RELEASE_COMPLETE` was issued. Existing
fixture checks from tasks 014/015 are retained; no duplicate physics is requested.
