# HP3 encoder scale and conditioning

The known-radius model does not have an unavoidable scale gauge in the tested geometry. Its weak directions depend sharply on where measurements are taken. Allowing a common unknown radius introduces an exact scale gauge. An additional known distance can remove that ambiguity, but it does not eliminate axis-dependent model bias. No change to automatic calibration is supported yet, and the sub-millimetre target remains unmet in the available physical evidence.

## Controlled geometry

[The reproducible experiment](scratchbook/gauge.py) uses four range differences at each of 80 points relative to an unknown reference position. Four anchors form a generic tetrahedron. Six parameters describe their geometry after rigid translation and rotation are fixed, and the reference and all sample positions are nuisance parameters. Distances are in mm, common radius 30 mm. This is an ideal static point-ranging model, not the production ellipse objective and not a feasible-motion or force simulation. Random seed is 917. The script prints [the numerical results](scratchbook/gauge-results.txt); [the original single-output run](scratchbook/gauge-results.json) retains the first stage.

For wide random position changes, the 320 by 249 Jacobian has rank 249. After projecting out nuisance positions, the six anchor singular values range from 0.6234 to 0.03713. For a narrow region of the same 80-point count they range from 0.02964 to 0.0009230. A noiseless wide-data nonlinear fit initialized near truth recovers all four anchor coordinates within 6e-12 mm. This establishes local identifiability for this constructed case, not universal observability. The anchor-coordinate gauge also makes anchor A error identically zero; these errors are not directly comparable to machine-coordinate applied errors.

When the common radius is also unknown, simultaneously scaling anchors, sample and reference positions and radius is an exact invariance. The Jacobian scale-direction residual norm is 6.1e-12, and a finite 1% change in all these lengths leaves encoder differences unchanged within 3.5e-14 rad. A known physical length supplies external scale information. Known radii are the baseline assumption throughout the remaining tests.

With 0.03 mm independent Gaussian observation noise, one narrow sample gives errors A/B/C/D of 0/20.38/14.79/21.32 mm. This is one realization, not a reliability estimate. With axis-dependent proportional perturbations of +0.01%, -0.01%, +0.02%, -0.02%, wide-data errors become 0/1.65/0.85/2.33 mm while residual RMS is 0.0150 mm. A heavily weighted exact 3000 mm A-B distance changes those errors to 0/~0/1.44/2.57 mm, with 0.0159 mm residual RMS. The perturbation is a generic bias probe; it does not demonstrate that motor friction produces proportional errors. The extra length is a distinct measurement assumption and is not used for selection. The near-exact constraint is weighted by 100 rather than algebraically eliminated. These examples show that low fit error and one measured span do not establish accurate anchors.

## Status and next experiment

No production change is supported by the results below. Wider spatial coverage is a promising design hypothesis, not yet a valid movement policy: the ideal random points do not enforce cable tension, obstacles or actual sweep kinematics. First compute the production Jacobian on accumulated real sweeps and use an observable, prior-declared design criterion to choose feasible sweeps. Then freeze the policy and run fresh independent HP3 worlds with verified baked friction and varied anchor layouts, scoring per-anchor applied errors only after acceptance. In parallel, measure return-to-start and force-dependent encoder repeatability to distinguish friction-induced model error from random noise. ## Projection boundary review

The initial fix `818eb53f` was limited to `EllipseCostFunction` when the dataset carried projection metadata. A [follow-up audit](evidence/projection-scope-audit.json) found that a direct held-out scoring call with `prefer_zero_tension_angles=True`, no spool model and an unannotated dataset still used the nonzero-force means. The standalone position objective could do likewise. Standard spool refinement normally rewrote both length fields from projected angles first, but history comparison did not forward the projection flag consistently and the raw collector file did not record the mode.

Follow-up commit `9a5dd6b5`, based on `818eb53f`, records projection mode in newly collected datasets, preserves or infers it when merging and rejects known mixed modes, recognizes the saved mode when fitting, and carries projection semantics through direct held-out scoring, the position objective and both history comparison paths. It accepts the kebab and camel spellings of the collector flag. The focused suite passed 188 Python tests and 38 Jest tests. The worktree's empty legacy forward-transform submodule was temporarily linked to the main checkout at its exact recorded commit `1923f39b3cf702d13087e7fe3cffecb15b20b0c5` for those tests and restored afterward. No new physical calibration was run with the follow-up commit. It needs independent review.

The fixed-cable summary is a separate unresolved model issue: the collector records one fixed length per cable after the two role-swapped sub-sweeps, while projected encoder angles exist per point. With spool refinement the rewrite uses a per-axis median of projected angles; in the known-radius path the post-sweep scalar remains. These commits do not make fixed lengths per-point projected measurements, and they do not establish the validity of commanded-force extrapolation. A later review found that unmarked legacy projected datasets were still mishandled by standalone scoring; the follow-up below addresses that observed format.

Independent review found a further boundary problem in `9a5dd6b5`: inference of unmarked legacy projected points happened during merge, but not during standalone fit or scoring, and declared metadata could contradict point records. The actual legacy `projection1206301/sweeps.json` has no mode metadata and contains valid four-axis `raw_angles_zero_tension_deg` arrays on all 240 points. Follow-up commit `3b4c60e0` introduces one shared mode resolver used by fit stage, ellipse cost, direct held-out scoring, position objective and merge. It recognizes this legacy format, validates projected arrays, and rejects mixed projected/nonprojected records, contradictory metadata and explicit projection requests on ordinary points. On the preserved physical file, fit without a projection flag now recognizes projection and the packed first drive/sensor lengths match the projected values -706.8082/485.1330 mm, rather than the later nonzero-force means -706.8017/485.0361 mm. The focused checks passed 198 Python tests and 38 Jest tests, with the same pinned legacy dependency temporarily linked and restored. These code changes require a new independent review.

The resolver cannot identify an externally authored or older projected format that omits the projected-angle field. The typed non-dictionary `SweepDataset` representation does not carry the projected metadata and is not supported for an explicit projection request. The fixed-length summary limitation remains unchanged. No new physical calibration was run after `3b4c60e0`; the numerical and physical accuracy limitations above still apply.
