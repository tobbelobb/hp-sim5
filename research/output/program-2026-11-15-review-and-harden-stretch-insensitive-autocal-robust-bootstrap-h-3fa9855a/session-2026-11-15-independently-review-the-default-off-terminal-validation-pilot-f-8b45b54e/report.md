# Independent review: common terminal validation

Reviewed `a2f47d14fa183337bd0b9242dd1fc91e76d3f25b` against the requested contract: freeze the admitted history, collect separate fresh observations, score each frozen candidate on those common observations with its own length model and offsets, then apply a scored candidate. The experiment is **not ready to rely on as a validated-model application path**. Several defects are inherited from existing collection or summary machinery, but the new terminal branch invokes them after freezing its candidates and therefore exposes the pilot to them.

No physics runtime was started and no parent pilot files were read or modified. The [counterexample tests](evidence/test_review.py) use synthetic data, mocked collection/application or small fragments extracted from the actual JavaScript parser and command builder. [Test results and environment](evidence/test-results.txt) record 102 passing selected tests, 15 deselected; this does not repeat the parent's reported 452-test battery. Counterexample tests pass when they demonstrate the defect.

## Findings

1. **P1 — A collector output alias can overwrite the training dataset.** The [terminal branch](../../../../autocal/autocal.py#L1340) replaces the first `--output-file` value, but [planning](../../../../autocal/_autocal_common.py#L1699) appends the user's collector arguments afterward. The [actual parser](../../../../autocal/control/cli/collect_sweep_data.mjs#L300) assigns the last `--output-file`, `--output`, or `--out`. With `--collector-args ... --out <training.json>`, a normal stop on the first fit directs the terminal collector to the training file. The mock collector overwrote its three sweeps with one and then the Python loop raised `FileNotFoundError` for the nonexistent terminal path; no candidate was sent, but the training data were lost. At the CLI wrapper this OSError becomes exit 1. The same raw-argument weakness exists in ordinary collection, but the new experiment promises a separate terminal dataset. `--sweepFile` and `--fixedTargets` can similarly override the planned config and targets; `--sweepFile` can request multiple sweeps. An explicitly forwarded `--hp-sim-reset` also remains in the copied command and can reset a connected browser simulation again; that path requires WebSocket mode. Resolve aliases and conflicting options before constructing the terminal command and verify its actual destination and acquisition configuration.

2. **P1 — Collector preparation can change firmware before a failed validation, and live RRF does not apply the selected spool model.** `--base-radii 30` and `--buildup-factor 0` cause [spool argument injection](../../../../autocal/_autocal_common.py#L516); the copied collector command can send `M666 R30:... Q0` [before collecting or scoring](../../../../autocal/control/behaviors/sweep_data_collection.mjs#L1453). If, for example, the current firmware radius is 25, a subsequent collection failure leaves that preparation change in place: the failure guarantee only prevents the later selected-calibration send. The extracted real command builder confirms the command; the failure aftermath follows from source, not a hardware trial. Conversely, when a fitted radius of 41 wins, [headless applies M669 and M666](../../../../autocal/autocal.py#L217), but [ordinary RRF sends only M669](../../../../autocal/autocal.py#L225). The mocked successful terminal run, with scoring stubbed to succeed, printed `M666 R41:41:41 Q0` but sent only M669, so the geometry may be used with the old collection radius rather than the model scored. Klipper deliberately skips M669 too. Treat collection-state changes and final model application as an explicit, consistently tested transaction; do not label a geometry-only send as application of a scored spool candidate.

3. **P1 — A stop file created during the terminal sweep is ignored until after a candidate is applied.** The [condition](../../../../autocal/autocal.py#L1334) checks the stop file once before starting; [_run_collection_command](../../../../autocal/autocal.py#L408) then blocks on the subprocess and the branch never rechecks it before scoring and application. In a mock, the collector created the stop file, returned one sweep, and the loop still sent M669 and returned 0. The collector may continue for the whole sweep, including force tuning, after the request. A request arriving during the last fit before that condition has a related bookkeeping defect: the branch skips terminal collection, but applies the old selection while retaining headless `stop_reason=patience`; with applied parameters that reason qualifies as normal completion. The latter race is reproduced with a fake headless context and the normal-completion predicate is covered by existing tests. Check for stop requests while collection runs and before application, and record the real reason.

4. **P1 — An interrupt after terminal scoring can fall back to an unvalidated selection.** The terminal-specific `KeyboardInterrupt` handler covers collection, scoring and artifact creation, but the [final application call](../../../../autocal/autocal.py#L1384) is outside that handler and inside the outer [best-so-far handler](../../../../autocal/autocal.py#L1473). A mocked `KeyboardInterrupt` in the first M669 send resulted in a second send from `_accept_best` and return code 0. With multiple histories, source inspection shows `_accept_best` re-runs the old history policy, which may apply consensus rather than the terminal winner. This does not prove the first send failed remotely; the transport outcome could be unknown. The counterexample uses one candidate, and the multi-candidate consequence is an inference from that policy. Interrupts *inside* collection or scoring correctly return 130 and do not send the candidate in our mocks.

5. **P2 — Force and collection options can invalidate the intended common protocol or add movement.** A saved complete force tuning is reused when no force override is present, but [any recognized partial force override](../../../../autocal/_autocal_common.py#L2685) suppresses reuse of *all* saved values. The collector's [default rule](../../../../autocal/control/behaviors/sweep_data_collection.mjs#L643) then auto-tunes if not all three forces were supplied; explicit `--auto-tune-force` also retunes. Thus a copied command can perform an extra tuning operation and collect at new forces even when saved tuning exists. This is reproducible from the real Python injector and extracted JavaScript predicate; explicit auto-tuning may be the user's general collection preference, but the terminal policy does not constrain or disclose its effect. In the other direction, JS accepts `--force-min` and `--torque-min` aliases that Python's override detector misses, so appended saved `--force-mid` can replace the requested value. These shared pre-existing inconsistencies matter to a one-sweep validation protocol, particularly with force profiles.

6. **P2 — Projected training and ordinary terminal data can be silently mixed.** The terminal evaluator infers projection solely from the validation dataset and never checks candidate training projection or machine/data compatibility. A synthetic candidate whose training points are marked projected receives a finite score against ordinary nonprojected validation points. The normal dataset merger rejects mixed projection modes; the terminal path intentionally does not merge and misses that guard. The current live collector rejects the explicit projected-collection flag, but an existing projected three-sweep dataset can be fitted and then followed by an ordinary terminal collection. Projected training disables home-offset fitting and has distinct angle/noise-mean semantics. Reject or explicitly define cross-mode comparison; our example demonstrates acceptance, not a measured real-world ranking inversion.

7. **P2 — The saved original-selection counterfactual and scored-versus-applied geometry can differ.** The [stage payload](../../../../autocal/autocal.py#L1337) saves `original_selection` metadata and a pre-summary, rounded M669, but not the actual original output after home compensation or its final M666. With synthetically valid independent extension evidence, the test scored the frozen anchors, saved the original M669, and observed the actual applied M669 translated by +0.300 mm in Z through the existing [summary path](../../../../autocal/autocal.py#L155). This is an intentional independently evidenced gauge-to-physical-home transformation, not evidence that the synthetic correction is physically wrong; nevertheless the emitted geometry was not the geometry directly scored, and the stage's claimed original M669 is not the command that the original policy would emit in this one-candidate example. Ordinary collector data currently do not supply this independent evidence. Preserve the full original and terminal output decisions, including compensation and spool parameters, or explicitly identify the transform and its evidence in the artifact.

8. **P2 — The measurement rewrite is not atomic and failure evidence is incomplete.** After collecting, the branch normalizes point roles and renames sweep IDs, then rewrites the only terminal JSON through [the normal JSON writer](../../../../autocal/json_schema.py#L33), which truncates before writing. An injected write error leaves `{"partial":` where a complete collected dataset had existed; there is no completed stage artifact to recover it from. The collector itself also writes its final JSON directly. Stage artifacts use temp-file replacement, but the dataset and stage are not committed as one transaction; `_unique_path` checks only the dataset path, so a pre-existing stage with a missing dataset may be overwritten. Headless partial-point journals may retain some data; non-headless collection has no equivalent guarantee. Preserve the original acquisition and atomically publish normalized data and state, including failure/interrupt information.

## What is supported and what is not

The flag is default-off. In the selected mocked tests, no-collect, active replay, a pre-existing stop file and exhausted step budget skip terminal collection. The common scorer rejects *matching current IDs*, uses the same residual settings for all candidates, applies each candidate's saved spool and home offsets to copies of the data, rejects nonfinite predictions, and selects a single finite-scored history candidate without a multi-candidate consensus. Existing and review tests exercise raw and projected synthetic data, nonzero winding, own-model radius comparisons, and unchanged input models/data. An offline terminal stage round-trip reproduced the synthetic scores and selection without calling the fit stage; the stage serializes admitted history candidates, validation data, options, evaluated scores and selection. Only each iteration's selected/admissible plan enters `history_candidates`; other fitted run variants are not preserved by this terminal stage. File paths to collection configs are recorded rather than their contents.

ID checks alone do not establish freshness. Collection restarts its local names at `sweep_001`, and the terminal branch replaces the source IDs with `terminal_001`, etc. *before* checking overlap. The test shows that copied training observations with a renamed ID pass. This is a provenance limitation, not evidence that the real collector reused observations. It also means the guard cannot independently prove the requested no-leakage property if a collector, override or file-handling fault returns old content. Source validation data are not passed to the fitting path in the normal terminal branch, and our mocks saw no additional fit; the output alias defect is an exception to the promised separate storage, not an observed refit of validation data.

On caught collection/scoring failure or interrupt, tests show no candidate send and return 2/130. All-infinite scores return 2 with an artifact and no selected candidate. `HeadlessSimulation` records these exit codes as failed/interrupted and `normal_completion=false`. This guarantee does not cover collector preparation changes, the later application interrupt, or unexpected filesystem exceptions; the latter reach the top-level CLI as exit 1. The interrupted collector can leave partial journals rather than a complete measurement file.

One common sweep improves comparability but is still one selected movement, with no independent check of absolute geometry. Fitted spool radius can trade against ellipse residual; same-data prediction is not proof of physical accuracy. The historical [whole-sweep audit](../../session-b7deb1bcc9cb418388273e2b7b9adc8c/report.md) found worse physical results on 5/11 recorded datasets, and the [earlier synthetic scorer study](../../session-7ec4260f7410499a96f6b6bfe9c3de59/report.md) established discrimination in one synthetic scenario, not online accuracy. These historical results concern different policies and source revisions and do not quantify this pilot. The parent’s bounded live HP3 nominal and soft-HP3/then-HP4 trials were outside this review; this report makes no claim about their outcome, performance, or hardware transfer. A sounder implementation and repeated independent physical comparisons could change the code-readiness or accuracy conclusion respectively.
