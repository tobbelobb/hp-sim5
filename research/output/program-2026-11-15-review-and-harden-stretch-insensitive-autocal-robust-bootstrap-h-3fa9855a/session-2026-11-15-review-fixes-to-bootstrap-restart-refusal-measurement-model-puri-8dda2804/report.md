## Finding

**P2 — A complete marker accepts a malformed or replaced dataset before starting simulation.** `bootstrap_state_error` in [rough_bootstrap.py](../../../../autocal/rough_bootstrap.py) checks only that the dataset exists when the marker says `complete`. A malformed JSON file therefore passes the early check in [autocal.py](../../../../autocal/autocal.py), and `HeadlessSimulation.__enter__` runs before the dataset is parsed. The [counterexample](evidence/check_edges.py) uses a fake context to prove entry without starting physics; [output](evidence/check_edges.txt) records it. A later interrupted non-atomic dataset rewrite, filesystem corruption, or replacement can leave an existing incomplete file with a complete marker. A valid but wrong/rough replacement also passes because marker and content are not bound. Validate the saved dataset before any physical/RRF startup and consider an integrity binding or explicit safe recovery policy. A marker is not a durability guarantee across power loss: `replace` is atomic at the namespace level, but neither file nor directory is fsynced.

A malformed legacy dataset containing a JSON list with a rough sidecar raises `AttributeError` rather than the intended unreadable diagnostic; it still stops before startup. An all-profiled legacy dataset with a stale rough sidecar is accepted. Conversely, a stale rough sidecar beside a valid constant-force legacy dataset is refused, so recovery requires selecting a fresh path or deliberately resolving stale artifacts. A legacy interruption before either marker or rough sidecar exists cannot be distinguished from an ordinary constant-force dataset. These are compatibility limits, not evidence that a new marked failed stage bypasses the gate.

## Verification and scope

- The marker is atomically replaced before the initial collection command. The early CLI and loop checks reject missing-dataset and existing-dataset pending/failed states; tests mock initial and refinement subprocess failure and a rejected geometry, then verify restart does not collect. An uncaught exception or abrupt kill leaves a non-complete marker and is refused on restart. We did not kill a real collector or test power failure.
- For ordinary profiled HP3/HP4 fits with no spool search, planning refuses both unavailable profile inputs and `--no-equal-strain` instead of creating a constant-force command. Profile/spool search is rejected in fitting. Historical projected markers are resolved before mixed-profile and spool guards, and offsets/noise means are disabled for projected data. Tests use synthetic records; actual historical file and physical force delivery were not independently checked here.
- The offline joint fit optimizes point positions, gauge-constrained anchors and its own `n-d` offsets together, with the same anchor bounds and gauge conventions as production. It receives the replay's unshifted `fit['dataset']`, with no ellipse-derived offsets or masks. Two finite-difference Jacobian checks on a synthetic HP4 start and second-stage solution gave maximum absolute errors `2.50e-8` and `3.79e-8`. The custom loss leaves the prior quadratic in both passes; offset residual weights are scale/sigma, so after SciPy's loss scaling the quadratic contribution remains weighted relative to the data scale. The check samples large prior residuals and confirms rho `[z,1,0]`. The exact synthetic fit converged in 17 combined evaluations.
- Its success/message and optimality describe the **second**, Cauchy solve; the first pass status is not reported, and `nfev` sums both passes. `ftol` convergence is local termination, not a global optimum, accurate anchors, or a validated uncertainty. The baseline shares the data extraction and anchor parameterization with production, and uses one seed unless the shared seed is unavailable. Its length extraction uses recorded `l_drive`/`l_sensor` and fixed-angle corrections; changing `raw_angles_zero_tension_deg` alone did not change input. For spool-fitted replay the ellipse uses a reconstructed length model while joint receives original recorded lengths, so comparisons are not necessarily on the same physical length model. Projected and spool combinations require explicit validation before interpreting comparative scores.
- The parent reports recorded full-dataset errors approximately 2.55 HP3, 8.52 soft HP3, 4.55 HP4, and 2.93 worn, with all current runs stopping by `ftol` at max 1000/tolerance 1e-8; earlier strict 500/1e-10 attempts failed to converge in two cases. Those are parent-reported simulation results, not independently replayed here. They do not show global optimality, robustness, or hardware accuracy. Matched held-out data, multiple starts, repeats and physical validation could change the assessment.
