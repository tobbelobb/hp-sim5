# Independent review of combined autocal hardening

Reviewed candidate `95d4ca4d` against `5f7189de`, including production commits `2fbf80cb`, `65e07479`, and `3d41c608`. The question is whether the combined collector, estimator, and output behavior supports robust and accurate calibration and a meaningful comparison with independent least squares. The candidate fixes the earlier profile collision and adds useful gates, but the bootstrap recovery path can bypass those gates. The evidence does not establish an accuracy improvement or hardware validity. No production code was changed in this review.

## Findings

1. **High: restarting an incomplete or rejected bootstrap bypasses rough assessment and equal-strain remeasurement.** In [autocal.py](../../../../autocal/autocal.py), `collected_bootstrap` is only `not dataset_path.exists()`, and the entire rough check and refinement sits inside that branch. The initial collection writes the main dataset before assessment. Each extra rough sweep rewrites it, while each completed refined sweep is written only to a sidecar until the whole refinement finishes. If the check rejects after nine extra sweeps, a profile fails, collection is interrupted, or the process exits during refinement, the main file is still rough data. Invoking the same command again sees the file and skips the whole gate; with more than three sweeps it enters ordinary replay, and with three it starts ordinary fitting. Since `is_equal_strain` is false, later collection also stays constant-force despite the default. Thus a failed gate does not remain failed across restart, and already completed refined sweeps are not resumed. This follows directly from the file writes and branch conditions; no live collection was interrupted in this review. Persist an explicit bootstrap stage and reference, resume or refuse incomplete work, and test failure at every transition with the same encoder origin and forces. A collector subprocess failure also raises `CalledProcessError`, outside the local `ValueError`/`LinAlgError` handler, so it does not produce that handler's diagnostic stop reason.

2. **Medium: a profiled dataset can silently plan a constant-force next sweep when profile inputs are missing.** [planning_pass.py](../../../../autocal/planning_pass.py) only adds a profile if `write_sensor_force_profile` returns true. That function returns false when W/N/Y or tuned force is missing; there is no refusal. A profiled historical dataset lacking one of these config fields can therefore collect a non-profiled sweep and append it; the next fit rejects the resulting mixed dataset in [fit_stage.py](../../../../autocal/fit_stage.py). The collection cost and an iteration are lost. Explicitly fail before collection if a profiled run cannot construct its next profile. Likewise `--no-equal-strain` applied to an existing profiled dataset leads to the same mixed-model conflict if another sweep is collected; it is a clean ablation only from a fresh constant-force dataset.

3. **Medium: historical projected profile flags are interpreted as actual profiled observations before projection is resolved.** The retired collector set `sensor_force_profile` even when it produced zero-tension projections. The new fitting guard checks those flags for mixing and spool compatibility before it resolves projected points, so a projected dataset with misleading historical profile markers can be rejected as a mixture or as profiled spool data. With `--no-fit-home-offsets` and no spool fit, consistently marked projected data are handled with raw projected values and offsets disabled. The intended scope of historical replay should be specified and tested against actual old projected files; a marker describing commanded profiles cannot establish the measurement model in this case.

## Assessment and evidence

- **Rough bootstrap.** [Reproduction](evidence/check_recording.py) and [output](evidence/check_recording.txt) independently recompute the recorded HP3 rough checks: three sweeps yield 76.15 mm maximum estimated parameter standard deviation and fail; four yield 18.19 mm and pass. Both starts converged and agree closely on this recording. Two starts are scaled versions of the same seed, not diverse basin exploration; the local Jacobian, 0.5 mm floor, and inlier test do not bound correlated stretch, force-model error, wrong geometry, or local minima. The 25 mm gate is not a certificate of final accuracy. Repeated scenes, noise and compliance changes, adverse seeds and held-out runs are needed.
- **Remeasurement and profiles.** On the uninterrupted path the final refined dataset is built from new profiled sweeps only, separately generated for each fixed configuration. Selector matching includes direction, fixed anchors and target lengths, and rejects missing or duplicate matches. Tests exercise these cases. Positive predicted tensions are filtered, but force clipping and endpoint extrapolation still mean a profile marker proves a command was supplied, not that actual forces achieved constant strain. Observed force and travel evidence is needed.
- **Offsets and validation.** The default is enabled and `--no-fit-home-offsets` genuinely disables the offset fit, including on profiled data. Frozen candidate offsets are applied once to its raw future sweeps in own-model scoring; the separate first-priority anchor comparison deliberately uses the latest estimation dataset as a common length model. That common reference may favor the latest candidate's offsets or spool model, so it should not be interpreted as an unbiased comparison of candidate predictions. The unit test verifies shift and no mutation, not history ordering across different fitted offsets. Projected data disable offsets after projection resolution, subject to finding 3. The CLI rejects simultaneous offset and spool fitting; profile/spool fits are also rejected. These guardrails limit supported combinations rather than validate them.
- **Physical home.** The helper's range equation and `a-q` sign follow its stated material conservation and gauge conventions; exact synthetic data verify that algebra. RRF and Klipper use an absolute negative tension-dependent flex term relative to geometric origin, so evidence must refer to the actual encoder and firmware reference, include routing and mechanical advantage, and avoid double correction. The gate requires independently supplied effective measurement and practically slack home extensions, uncertainty, rank and residual checks. Ordinary collection supplies none, so it cannot currently correct physical home. Provenance is a string, not evidence verification. The [home investigation](../session-2026-11-15-determine-and-implement-physically-justified-final-home-shift-co-fc8f5233/report.md) shows correlated wrong extensions passing the consistency gate. This opt-in algebra is not a physics or hardware proof; the fit's offset, extension and ellipse anchor references must be independently tied together.
- **Actual comparisons.** The intermediate `hp3-adaptive-2` run reports worst rounded coordinate error about 1.68 mm; source changed during the run, so it is not a frozen-candidate result. The earlier Fable d2 result was about 1.4 mm in a different single run, and is not a paired baseline. At iteration 5 of the intermediate recording, the production point fit reports 0.0300 mm line RMS and maximum coordinate difference 0.634 mm from its corresponding ellipse fit. Both use the same measurements and the point fit supplies the ellipse offsets: this is not independent least squares or a held-out accuracy comparison. Fable's independent least-squares study used direct-collector data and a different pipeline. A fresh final HP3 run was in progress outside this review and was not inspected or altered.

## Validation and next decision

Using the shared repository environment through `.venv/bin/python`, 52 focused bootstrap, home, prediction and CLI tests passed; another 23 pose, equal-strain, planning and projection tests passed. The two targeted JavaScript suites passed 30 tests. Reproduction reads the saved intermediate recording; no simulator or hardware was started. The failures above are code-path counterexamples, not measured accuracy losses. The existing focused tests do not exercise crash/restart at bootstrap stages, fallback to constant force, or projected historical markers with spool mode.

Before claiming robust improvement, fix and test restart and model purity, then compare the real frozen production ellipse solver and an independently implemented least-squares fit on the same retained observations and disjoint held-out sweeps, with and without offsets and profiles. Include absolute and translation-aligned errors against known truth, equal collection budgets, repeats over seeds and physical parameters, and failed runs. A favorable paired distribution and independently measured home-reference evidence could change this assessment; one simulation or a small residual cannot.
