# Slip recovery, simulator startup and fixed-encoder modeling

Objective: recover and recollect after fixed-motor drift, automatically configure closed-loop/layering/Rerun, and determine where small fixed encoder errors enter optimization.
Accepted steering: user prefers reduced force and continuation after a slip, no force sensor dependency. Inspect completed trial-005, preserve recordings and user browser. Evaluate optimization placement rather than introducing an unvalidated refinement algorithm.

Hypotheses: E1 recovery lowers commanded forces, restores fixed targets, discards failed direction points and finishes; E2 simulator settings update resources/UI and recording connection is acknowledged; E3 fixed pointwise encoder variation is discarded by the current cost model; E4 trial-005 ended because its final fit offered no valid next sweep, rather than a collector timeout.
Budget: three isolated production JS/RRF collection runs, each with a 300-second wall subprocess deadline; the third verifies corrected force metadata and mean-angle checking. One actual local recording startup check, with a ten-second receiver startup deadline, and one frozen-residual comparison. No hardware/user UI control. Preserve failed experiments.

E1 supported: test-only forced open-loop physics plus an explicit 6.44246 N measurement command creates 8.01-degree fixed B drift. The production collector holds all motors, halves mid/max/explicit sensor commands, returns to origin and restores fixed targets. Both directions finish with 20 accepted points, B span .47 degrees, and maximum fixed error .38 degrees. Final dataset excludes the failed direction and retains recovery provenance. The first probe exposed an inaccurate pullout metadata calculation when a sensor override was present; a corrected final probe matches actual commands (pullout 2.27272 N, sensor 3.22123 N). No universal hardware recovery guarantee is inferred.

E2 supported: resource/toggle tests confirm closed loop, all layering flags, rebaking on an actual layering change, and idempotence. The ordinary closed-loop bootstrap including size measurement completes six directions/60 points with max travel431.982 nominal mm (raw539.977), 1677.844 simulation seconds in 96.98 wall seconds. Requested speed is never used to infer elapsed simulation time. A real receiver/FlightRecorder connection confirms first physics acknowledgement, preserved existing session and three sampled physics observations in one RRD, without rejected messages. Initial recording harness used the logger's wrong argument type and produced an empty RRD; preserved as failed test evidence, then corrected. Tests cover metadata before browser connection.

E3 supported: finite residual arrays remain exactly identical when trial-005 fixed raw angles are perturbed by ±0.7 degrees without changing drive/sensor inputs. Reversing the fixed encoder associations in trial-004 also leaves spool-transformed pointwise residuals identical because the median is unchanged. The current model loses pointwise fixed geometry, despite retaining raw encoders and aggregate cogging/flex noise.

E4 supported: trial-005 has 11 sweeps/220 points, fixed angle spans at most 0.01 degrees. Its final iteration 9 fit has rank 0/12, D_z=0, underconstrained sentinel100, and no candidate. This explains the lack of a final verdict. PjRt warning internals and full optimizer recovery are not investigated here.

Status: complete. Proposed optimization extension is documented rather than implemented: use candidate-dependent per-point fixed lengths in the NumPy/JAX pointwise paths and propagate uncertainty; preserve raw evidence and apply the same model to held-out predictions. Full optimizer accuracy and real hardware recovery remain untested. Final checks:23 JS suites/126 tests, a focused 4-test recovery rerun including one added floor regression, and17 Python tests pass. Next decision: reload the visual browser and collect with the new startup/recovery path; evaluate the proposed objective change in a separate controlled calibration experiment.
