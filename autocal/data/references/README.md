# Reference data provenance

The eleven datasets in [`DATASETS`](../../tools/regress_calibration_logs.py)
were collected from browser physics simulation with `autocal/autocal.py --sim`
and no explicit `--dataset` (maintainer-confirmed). Earlier versions used
`active_calibrate.py`; the historical [autocal README](../../README.md) describes
the equivalent workflow. These are recorded simulation measurements, not the
analytical synthetic sweeps generated by unit tests.

Start with the JSON: `machine_type`, `num_anchors`, `dimensions`, `timestamp`,
`config` (units, M666 before/after collector changes, conversion factors,
`notes` overrides, force/noise settings), and each sweep's `metadata` (feed rate,
sensor force, settling). Fields vary by dataset age. For example,
[`23_april_2026.json`](23_april_2026.json) records forced base radii of 30 mm and
buildup factor 0.636619. Use recorded values rather than today's defaults.
For fitting/regression, the JSON and `DATASETS` supply the inputs and expected
truth; reconstructing the original command/browser session is not required.

To inspect a snapshot or follow subsequent corrections, run from the repo root:

```bash
git show 5ed1c4a2:autocal/README.md
git show 5ed1c4a2:RRF/run/vsd/sys/config_hp3.g
git log --follow -p -- autocal/data/references/23_april_2026.json
```

RRF configurations live in `RRF/run/vsd/sys/config_*.g`; machine/config aliases
are in [`machine_type.mjs`](../../control/primitives/machine_type.mjs).
`hangprinter_4`/`hp3` uses the HP3 configuration, not the HP4 scene name.
At `54ab341b`, Slideprinter scene definitions were under `examples/usd_scenes/`
and browser selection/mapping in `hp-sim/assets/hp-sim.js`; at `5ed1c4a2`,
HP3 definitions were in `public/usd_scenes/hp3_rigid_body.usda` and
`hp-sim-3d/app/`. Inspect that revision's selection/layering code when needed.
The regression runner's `SIM_*_TRUE_*` constants define the expected effective
anchors/radii; raw scene attachment positions/base spool radii are different
quantities.

Known corrections: `0fdf8060` changed stored M666 R from 38.72 to 30 in the three
layered Slideprinter fixtures; `f193251c` corrected the fifth-HP3 replay's
`--base-radii` from 39 to 30. Saved `.log` files are calibration **replays**:
their `; command:` and planned `collect_command` lines describe that replay,
not the original collection. The introduction messages do not preserve an
exact collection command or all browser UI overrides; do not invent them.

For new collections, use [extended autocal reference data](extended-reference.md)
to preserve physics, timestamped communication, original collection output,
scene/config provenance and numerical stage inputs in one Rerun recording. The
manual procedure requests 25× in the visual browser, with sampled physics by
default and timing based on the observed simulation clock. Existing fixtures retain the
historical limitations described above.

For new fixtures, put the collection revision and any nondefault browser
scene/settings in the commit message. Keep measured configuration in the JSON;
there is no need to duplicate it here.
